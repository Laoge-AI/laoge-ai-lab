# 第二版：先让访客看懂服务，再看实验

## 反馈中反复出现的问题

四位读者对第一版的反馈集中在：

- 首屏右侧像一张未解释的实验笔记，不清楚它与访客有什么关系。
- “把AI用在具体的事情上”过于宽泛，身份与具体能力出现得太晚。
- 001/002编号与技术分工不能直接说明做了什么、对谁有用。
- 缺少从咨询到试点的明确路径，也缺少报价、周期、维护和验收的说明。
- 联系需要绕到小红书或公众号，个人微信与邮箱不够直接。

这些反馈用于定位理解障碍，并不代表已经完成市场需求或成交验证。

## 修改决策

| 第一版 | 第二版 | 想验证什么 |
| --- | --- | --- |
| 先看抽象定位与工作笔记 | 首屏写明AI知识库、客服和官网；先介绍老鸽与交付背景 | 读者能否更快说出能帮什么 |
| 右侧模拟实验流程 | 三类业务问题与对应能力，可点击查看例子 | 读者能否找到与自己的关系 |
| 以实验编号开头 | 以客服和官网场景命名，写出问题、已验证结果与合作切入点 | 看案例后能否判断适用性 |
| 泛化的“怎么做事” | 发需求、约定试点、实施验收、决定扩展和维护 | 能否理解第一次合作怎么开始 |
| 联系引导到内容平台 | 个人微信二维码、邮件链接、复制邮箱 | 是否更容易发起具体沟通 |
| 公众号与需求沟通混在一起 | 将公众号作为可展开的后续更新入口 | 服务咨询与内容关注是否更清楚 |

## 用户已确认的信息

- 过去有系统项目交付经历，网站只做概括性描述。
- 现有公开AI成果为个人实验；本站为自用案例，分别保留性质与验证边界。
- 合作方式采用按范围评估后报价，不发布未经确认的固定价格与工期。
- 已提供个人微信二维码和公开联系邮箱。
- 暂时沿用现有头像，缩小到身份信息旁边。

## 案例证据的呈现

AI客服继续使用真实测试记录的摘要：批量采购需求经用户同意后转人工；保留知识库、业务规则和人工接手的测试范围。

建站例子同时区分模拟官网与本站自用主页。第一版实际截图保存在 `public/images/homepage-v1.png`，作为可核对的展示材料。

## 第二轮读者测试

先不讲解，给读者短时间浏览，再问：

1. 这个人是谁？你觉得可以找他做哪一件具体事情？
2. 哪个例子与你的情况有关？你还缺什么证据？
3. 如果现在想咨询，你会点击哪里？第一次需要提供什么？
4. 你是否看懂价格和周期如何确定？哪些部分仍然不清楚？

记录原话、读者是否接近目标客户，以及具体卡住的位置。不把“页面更清楚”直接当成“客户愿意付钱”。
